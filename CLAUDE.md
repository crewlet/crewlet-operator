# Crewlet Operator — conventions for AI coding agents

A Kubernetes operator (Kubebuilder v4, `go/v4` layout, controller-runtime)
that runs [Crewlet](https://github.com/crewlet/crewlet) companies from
`crewlet.ai` custom resources. Public, MIT-licensed repository: everything you
write is read by strangers, so it has to stand on its own. Read
[CONTRIBUTING.md](CONTRIBUTING.md) before a non-trivial change; this file is
the short form.

## Layout

```
api/                  separate Go module github.com/crewlet/crewlet-operator/api
  v1alpha1/           the crewlet.ai types, markers, generated deepcopy
cmd/main.go           the manager
internal/controller/  reconcilers: two keyed by Company, the runtime one
                      (Accepted; the engine's Secrets, data StatefulSet,
                      Services, routes and NetworkPolicies, and the seat
                      pools' StatefulSets, Secrets, PodDisruptionBudgets
                      and broker and seats policies) and the config one
                      (the company document, the secret store, the seats'
                      pauses and where each seat runs, from GET /fleet,
                      the parts' status); and the EngineClass one
                      (its Accepted: the Secrets and Gateways it names
                      exist); the other kinds
                      are reconciled through the Company they reference
  testdata/gateway-api/  the Gateway API CRDs envtest installs
                      (make gateway-api-crds)
internal/engine/      typed client for the Crewlet engine's API (REST, and
                      the pause tools of its operator catalogue over MCP);
  enginetest/         runs the real engine (bin/crewlet, Crewlet's main) for
                      a test, and reads its module source for a test that
                      holds a copied list or function to it
internal/render/      pure render of the crewlet.ai objects into the company
                      document (Tier B) and a data or seat pod's
                      crewlet.yaml (Tier A)
internal/secretref/   the identity of one referenced Secret key
internal/secretsync/  pushes referenced Secret values into the engine's
                      encrypted store under StoreName; render writes the
                      same names as ${NAME}
config/               kustomize: CRDs, RBAC, manager, samples (Kubebuilder layout);
  admission/          the ValidatingAdmissionPolicy that holds the manager
                      to the objects it makes
dist/chart/           Helm chart, generated by `make chart`, partly curated
docs/                 user docs; docs/reference/api.md is generated
adr/                  decisions that bind more than one package
test/crd/             envtest suite for the CRDs: every CEL rule, defaults, samples,
                      and the objects docs/getting-started.md applies; the
                      CLIAgent sign-in and model rules, the guide's table
                      of them and the claudeModel enum, against the engine
test/docs/            reads the manifests a doc hands to kubectl, and the
                      tables it states, for the suites; and holds docs/ to
                      its index, its links and anchors, and the engine's
                      pages it links (the documentation site's contract)
test/chart/           envtest suite for the chart's RBAC and admission policies,
                      acting as the subjects they bind (needs bin/helm)
test/e2e/             kind-based e2e suite (build tag e2e)
test/envtestbin/      finds bin/k8s's newest test binaries for a run outside make
test/enginecommit/    reads the Crewlet commit an engine image was built from,
                      for make crewlet
scripts/              the DCO sign-off gate and its tests
hack/                 generator configuration
```

`api/` is its own module so consumers (a control plane that provisions
tenants) import the types without controller-runtime: it may depend on
`k8s.io/api` and `k8s.io/apimachinery` only (a depguard rule enforces it). The root module
requires it via `replace ./api`. Every Makefile Go target runs in both
modules.

## Checks

```bash
make check       # everything CI runs except e2e and the image: run it before every commit
make test        # unit + envtest + engine + chart suites (both modules, -race)
make lint        # golangci-lint, both modules
make crewlet     # bin/crewlet at CREWLET_IMG's commit (Crewlet's main), or at
                 # CREWLET_VERSION; prints it; a go test outside make needs it (or CREWLET_BIN)
make helm        # bin/helm: test/chart outside make needs it (or HELM)
make test-e2e    # kind cluster, Docker 28+; pulls the engine image too (make
                 # crewlet-image, CREWLET_IMG; another image already here runs
                 # as it is); KIND_CONFIG names a cluster config of your own;
                 # a failed run leaves the cluster: make cleanup-test-e2e deletes it
make help        # every target
```

Every tool is pinned in the Makefile and installed into `bin/`, and the
engine is installed there unpinned (see Versions); never rely on a tool from
PATH.

## Generated files — never edit by hand

`api/**/zz_generated.*.go` (`make generate`), `config/crd/bases/*`,
`config/rbac/role.yaml` (`make manifests`), `dist/chart/templates/**`
(`make chart`; `NOTES.txt`, `_helpers.tpl` and `tenant-provisioner/` are
curated by hand), `docs/reference/api.md` (`make api-docs`), `PROJECT`. After
touching types or RBAC markers run `make manifests generate chart api-docs` and
commit the output; `make verify-generated` fails otherwise. Scaffold new kinds
with `bin/kubebuilder` (`make kubebuilder`), with no `--group` (the group is
the domain, `crewlet.ai`), and keep every `// +kubebuilder:scaffold:*` marker.

## Principles

- **Credentials by reference, never by value.** Every credential is a
  `SecretKeyReference` / `SecretReference` to a Secret, in every position
  Crewlet tags as a credential (`secret:"true"` in its `internal/config`). No
  field accepts a secret literal; `engineConfig` may not name a block that
  holds one. `docs/concepts/credentials.md` maps each position to its field. Never put a secret value into a pod template, env var,
  annotation, status, event or log; values go only into the engine's
  encrypted secret store.
- **The company document is applied whole.** The config reconciler renders
  every child of a Company into one document and applies it atomically, or
  not at all. A failure is reported on the child that caused it
  (`ResolvedRefs=False` / `Applied=False`); the last good revision keeps
  running. Never apply a partial document.
- Same-namespace references only; only the cluster-scoped `EngineClass` may
  reference another namespace.
- The operator never creates namespaces.
- No admission webhooks in v1alpha1: validation is OpenAPI + CEL, so install
  never needs cert-manager.

## API conventions

Follow the Kubernetes API conventions: spec/status with the status
subresource; `metav1.Condition` with `observedGeneration` and a `Ready`
summary; PascalCase enum values; `+listType=map` / `+listMapKey=name` lists,
never maps (label, annotation and selector maps excepted); `…Seconds` integer durations; CEL rules (immutability via
`self == oldSelf`, unions, cross-field) each with a clear message; category
`crewlet` on every kind; `app.kubernetes.io/*` labels and owner references on
everything the operator creates. Every validation rule gets a case in
`test/crd/` (envtest) proving the API server refuses what it must, with the
rule's message; kube-api-linter (`make lint`) holds `api/` to the conventions.
Every typed field maps onto one Crewlet field, named in its doc comment. v1alpha1 may break freely; from
v1beta1 the Kubernetes deprecation policy applies.

## Code rules

- Comments explain WHY, especially why the obvious alternative is wrong.
- No TODO/FIXME, stubs, placeholders, or dead code. Fix root causes; no
  `//nolint` without a linter name and a written reason.
- Tests must be able to fail.
- **No license headers** in source files; `LICENSE` covers the project.
- Logging: controller-runtime's logr, structured key/value pairs (logcheck
  enforces the Kubernetes conventions).
- Docs are part of the change: update `docs/` for any API, behaviour,
  deployment or make-target change. `docs/` is also published on the
  documentation site: a new page gets a row in `docs/README.md`'s tables (its
  navigation), and the engine's pages are linked as
  `https://github.com/crewlet/crewlet/blob/main/docs/…` URLs; `test/docs`
  fails otherwise (CONTRIBUTING.md, "How the docs are published").

## Versions

Everything is on its newest release, pinned exactly: Go modules by version,
images by digest with the tag in a comment, GitHub Actions by full commit SHA
with the version in a trailing comment. Establish "newest" from the source
(`https://proxy.golang.org/<module>/@latest`, the project's releases, the
registry), never from memory. A version held back on purpose carries its
reason in a comment at the pin. Indirect Go dependencies stay where the direct
ones put them (the k8s.io modules move in lockstep). CONTRIBUTING.md,
"Latest versions", lists the pins Dependabot cannot see.

The Crewlet engine is the one deliberate exception: never pinned. Every
suite runs Crewlet's `main` as `ghcr.io/crewlet/crewlet:main` publishes it
(`CREWLET_MAIN_IMG`, `CREWLET_IMG`'s default; `make crewlet` installs the
commit it was built from), because the operator is tested against what
Crewlet ships next: a Crewlet change that breaks it fails the operator's
next run (ADR-0002). `CREWLET_VERSION` runs another engine, to
reproduce a run whose log names it. A release keeps the engine it was tested
against (`ghcr.io/crewlet/crewlet-operator/engine:<version>`, RELEASING.md).
An engine function the operator copies a run-time decision from is
fingerprinted (`internal/render/mirror_test.go`): when one changes, read it
against every operator file named and record its new digest.

## Commits

- `git commit -s` always (DCO; `make check` and CI fail without the trailer).
- Subject `type(scope): summary`: imperative, lowercase, no period, ≤72
  characters. Types: feat fix docs refactor perf test build ci chore revert.
  Scopes: api, controller, render, engine, secretsync, chart, e2e, ci, docs,
  build, deps, scripts.
- One logical change per commit. The PR title follows the same form and is the
  release note.
- Never change git config; never push unless asked.
